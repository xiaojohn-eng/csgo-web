# Source 地图仿真数据身份

原始 BSP 相同，不能证明两次导出的碰撞相同。Source 房间使用 `level`、`collision`、`navigation` 三个已验证文件的完整 SHA256，再按 T-AK、T-M4、CT-AK、CT-M4 固定顺序加入四套原版姿态数据身份、普通子弹伤害、步枪handling、落地回调、慢走和角色几何移动版本，构成 `simulationVersion`。仅显示文件更新不会改变这一版本；用于服务端命中盒的姿态数据更新会改变版本。

浏览器读取并验证这三个文件后生成身份，连接时发送；服务器独立验证本地文件后生成身份。创建和加入房间都必须完全相等，缺失身份也会拒绝。房间元数据和快照带同一字段，浏览器收到不匹配快照会退出。旧港口房间不需要这一字段。

`scripts/source-simulation-identity-smoke.ts` 使用隔离本地服务器、实际 SDK 和原始地图数据，验证旧/缺失身份不能创建或加入，失败创建释放房间代码，失败加入不占战斗席位，正确双端收到一致快照，离开后房间清空。证据保存在 `output/tests/source-simulation-identity.json`，其中记录了该次实际数据身份；它验证版本机制，不证明碰撞几何或浏览器移动正确。

修正碰撞后必须一起更新浏览器与服务器，并重新运行真实页面移动检查。服务器运行期缓存自己的已验证数据，因此仍需重启候选服务，不能只覆盖正在服务的静态文件便视为完成。

原始资源使用固定 URL，所以服务器为 `/source/` 文件发送 `Cache-Control: no-cache`，允许浏览器用 ETag 验证未变资源并收到 304，避免一小时缓存保留旧清单和旧碰撞。SDK 检查也实际验证了这一响应。
