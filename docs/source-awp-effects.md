# AWP 自己的两条特效

AWP 不是"一把步枪"。`items_game.txt` 在自己的 `visuals` 块里给每把武器各写 `eject_brass_effect` 与 `tracer_effect`，AWP 的两条**都不是步枪那两条**：

| | AWP | AK-47 / M4A4 | Glock / USP / Deagle |
| --- | --- | --- | --- |
| `eject_brass_effect` | `weapon_shell_casing_50cal` | `weapon_shell_casing_rifle` | `weapon_shell_casing_9mm` |
| 抛出的模型 | `shell_50cal`（57.067 模型单位长） | `shell_762`（38.7） | `shell_9mm`（19.15） |
| 初速（发射器局部单位） | `[90,55,30]`..`[120,85,55]`，**三轴全为正** | `[120,−15,50]`..`[150,5,75]` | 同步枪 |
| 撞面留存（`amount of slide`） | `0.2`（三条里最紧） | `0.4` | `0.4` |
| `tracer_effect` | `weapon_tracers_rifle` | `weapon_tracers_assrifle` | `weapon_tracers_pistol` |
| 曳光初速 | `13000..14000` | `13000`（定值） | `12000..13000` |
| 曳光半径（半宽） | `4..7` | `3` | `2..3` |
| 沿线起点偏移 | `80` 单位 | `20` 单位 | **没有这条算子** |
| 带子时长 / alpha | `0.19..0.20` / `140..180` | `0.084..0.093` / `160..175` | `0.044..0.05` / `140..205` |

两条系统的实现与字段逐条见 [原作弹壳](source-shell-casings.md)、[原作曳光](source-tracers.md)。这一页只讲 **AWP 自己的那一条**在真实游戏里是怎么被画出来的，以及为此修掉的一个真实缺陷。

## 一个真实缺陷：AWP 的抛壳走的是端口自己的替身

弹壳系统整体接进射击路径后，AWP 那条通路漏接了：`scene.ts` 的 AWP 抛壳回调里仍然是端口自己的 `this.effects.eject(...)`（一个不读发货系统的占位效果），而 `sourceShells.spawn('awp', …)` 只在别的武器上被调用。也就是说**AWP 从来没有抛过 `weapon_shell_casing_50cal`**——尽管表里 `weapons.awp` 一直指着它、单测也一直绿（单测钉的是表，不是这条回调）。

现在这条回调按武器自己的两个发货事实走：**用哪条系统**由 `sourceShells.table.weapons.awp` 决定，**从哪抛**由武器自己模型里的抛壳附件（`v_snip_awp.mdl` 自带的第 2 号附件；第 1 号是枪口）决定，**怎么落**由 `.50cal` 系统自己的重力、阻力、寿命与碰撞响应决定。只有在系统未入库时才回落到端口自己的替身——"拿别的顶替"不是可选项。

**抛壳的时刻也不是开枪的时刻。** `.50cal` 的弹壳是在枪机循环里被甩出来的（`onSourceAWPBrass` 由 AWP 自己的播放链路在自己的枪机相位上调用），比这一枪晚；验收因此等的是**黄铜提示事件**（`sourceAWP.brassEvents`），不是射击事件。

## 真机验收

`scripts/run-playwright-awp-effects-validation.mjs`（真实浏览器 + 局域网服务 + 训练局，`output/playwright/source-awp-effects-ingame.json`）。AWP 不是出生武器，所以脚本先**从游戏自己的商店里买一把**，再按真实按键路径开枪：

| 断言 | 实测 |
| --- | --- |
| 枪是从游戏自己的商店买的 | 主武器 `vandal` → `awp`，钱 `16000 → 11250`（花 4750） |
| 抛的是武器自己那条系统与模型 | `weapon_shell_casing_50cal` / `shell_50cal` |
| 抛壳提示真的到了（不是开枪就抛） | `brassEvents = 1` |
| 初速落在系统自己的区间内、且不是被归一化过的方向 | `3.4668 m/s`，区间 `2.785..3.988`（`[90,55,30]`..`[120,85,55]` × 0.0254） |
| 模型单位换算按表施加 | `modelScale = 0.001`（模型单位→米），与表里 `modelUnitsToMetres` 一致 |
| **画出来的 .50 弹壳就是它自己那么大** | `0.05706711 m`（= 该模型自己的最长尺寸），与表的 `longestSizeMetres` 逐位相等 |
| 它真的飞了、并且由关卡回答 | 0.4 s 时飞行 `1.2064 m`、0 次弹跳、`refused = {}` |
| 撞面留存用的是 AWP 自己那条（三条里最紧） | `slide 0.2 < 步枪 0.4`（表值与绘制共用同一份） |
| 曳光是武器自己那条系统与材质 | `weapon_tracers_rifle` / `materials/particle/particle_spark.vmt` |
| 带子落在这一枪自己的线上 | 线长 `21.183 m` = 带子 `19.151` + 起点偏移 `2.032`（1e-6 内），终点是权威落点 |
| 起点偏移是 AWP 自己的 80 单位（步枪 20） | `2.032 m = 80 × 0.0254` |
| 速度、半宽、alpha 都落在系统自己的区间 | `340.3 m/s`（`13000..14000` → `330.2..355.6`）、半宽 `0.15195 m`（`4..7` 单位 → `0.1016..0.1778`）、`alpha 0.5954`（`140..180`/255） |
| **比步枪宽**（这是它自己 `Radius Random` 说的） | 0.15195 ≠ 步枪的 `3` 单位 `0.0762`，且区间下界更高 |
| 带子仍是自己的上限 12.7 m 长起来 | 逐帧 `2.087 → 4.187 → 6.287 m`（age 0.0166/0.0333/0.05），与 `12.7 / 0.101 × age` 相符（125.7 m/s） |
| 逐帧：每帧都可见、都是同一条系统 | 抓到 3 帧，`drawn` 全为真、`system` 全为 `weapon_tracers_rifle` |
| 页面错误 | `errors = []` |

**为什么曳光只有 3 帧、带子只长到 8.39 m：** AWP 这一枪的飞行只有 `0.0563 s`（19.151 m / 340.3 m/s），而带子的斜坡要 0.101 s 才长满。逐帧记录里最后一帧写在 age `0.0667 s`（`12.7 × 0.0667 / 0.101 = 8.387 m`），与从写出的顶点量回的 `8.3870 m` 逐位相符——**带子没长满是它自己没飞够，不是被截断**。

**为什么这枪打的是 21 m 而不是贴脸的 3.6 m：** 出生点正面就是墙，那一枪的曳光只飞 11 ms（比一次往返还短）。脚本先把视角转到空旷方向，才拿得到一条能逐帧看见的带子。视角**不抬**——抬高会让子弹飞过地图自身的天空，没有落点就没有弹着，也就没有曳光。

**AWP 是栓动的，很少开火，所以每发都要认领它自己的那份记录。** 页面内观察器按「射手:seq」把结果与帧收在自己的表里（`local:` 前缀），不读"最后一条曳光"——机器人也在开枪，`lastShot` 大部分时间属于它们。抛壳的 spawn 记录同样**按系统名**认领：审计里那个共享的 `lastSpawn` 属于最后开枪的人，而机器人握的是步枪。

## 第一人称枪口闪光：同一系统名，另一个实例

`items_game.txt` 把第一人称与第三人称**分成两列**，AWP 这两列写的是同一个名字 `weapon_muzzle_flash_awp`，但它画在两个不同的地方：别人看到的那次在**世界武器**自己的 `muzzle_flash` 附件上（[原步枪第三人称枪口](source-rifle-muzzle-particles.md) 那一轮已实现），射手自己看到的那次在**视图模型自己的场景**里、挂在**视图模型自己的枪口附件**（`v_snip_awp.mdl` 的第 1 号附件；第 2 号是抛壳）上。

在这之前射手自己的那次**不是原件**：`this.muzzle` 一直是端口自己的一个圆锥替身（亮 0.22 秒），只有手枪那一系把它藏掉、改用原件粒子。现在 AWP 也照同一条规矩走——按武器自己的 `muzzle_flash_effect_1st_person`（`game/source-first-person-muzzle.ts`）决定画哪条，原件画了就把替身藏掉。**哪条系统由武器自己那一列决定**，所以步枪系的 `weapon_muzzle_flash_assaultrifle`（本 build 只入库了第三人称的用法）在这一列上被报成"未入库"、**保留替身**，而不是把世界那份程序换个名字顶上来。

这条链就是 `weapon_muzzle_flash_awp` 派发的猎枪连续火焰与它的辉光：火焰 7.5 ms 内发 9 粒、沿 +X 从 0 扫到 29 单位（半径 15→1 单位、alpha 70→100、寿命 25→17.5 ms），辉光 6 ms 内发 3 粒、扫到 25 单位（半径 22→6、alpha 50→70）。真机验收里**画出的正是这两组数字**：

| 断言 | 实测 |
| --- | --- |
| 是武器自己那一列点名的系统 | `weapon_muzzle_flash_awp`（派发的火焰是 `weapon_muzzle_flash_huntingrifle_main`） |
| 发了一次、两组都画了 | 1 次爆发、**9 个火焰精灵 + 3 个辉光精灵**（正是原件自己的 9 与 3） |
| 锚在视图模型自己的枪口附件上 | 视图模型场景里的 `[0.1275, −0.0867, −1.3973]`（沿枪身向前 1.40 m）、附件 `1`、方向是单位向量 |
| 端口自己的圆锥没有顶替它 | `placeholderVisible = false` |
| 每一个精灵都在枪口前方、且不超出它自己的扫掠 | 最远一个 0.7624 m = 自己的 29 单位扫掠（0.7366 m）+ 自己的 1 单位出厂偏移（0.0254 m），无一粒在枪口后方 |
| 半径与 alpha 都在它自己的窗口内 | 火焰半径 `0.0254..0.381 m`、alpha ≤ 100/255；辉光半径 `0.1524..0.5588 m`、alpha ≤ 70/255 |
| 逐帧记录 | 抓到 1 帧（整段只有约 25 ms，比一次往返还短），帧内 9 + 3 行位置全部来自渲染器自己写出的顶点 |
| 辅助：帧缓冲截图 | 1995 KB 的 `output/playwright/source-awp-flash-first-person-frame.png`（读回被拒绝时会如实写明而不是当作证据） |

## 仍然缺的

`.50cal` 自身的 `amount of bounce 0.8` 在这一枪里**没有被真机执行到**（0 次弹跳），它与 `slide` 一起只由表值与单测钉住；抛壳附件是武器自己的抛壳骨（PCF 只说速度是发射器局部的，**没有点名附件**）；开镜时整支视图模型枪都不画（`showGun` 为假），所以那一枪的闪光也随枪不画，原件在开镜时是否仍发射这条系统没有录像对照；这一页的三条断言都只读端口自己画出的东西，**与原件录像的逐帧对照仍然没有**。步枪系的第一人称那一路走的是同一条判据与同一套做法（同一系统名的第二个实例、锚在视图模型自己的 `muzzle` 附件上），另有一次独立真机验收，见 [原步枪第三人称枪口](source-rifle-muzzle-particles.md) 末节。
