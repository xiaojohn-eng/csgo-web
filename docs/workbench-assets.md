# Valve 旧 CS:GO Workbench 私有参考资产审计

审计日期：2026-09-08。已校验、解压、清点并转换 **34/34 把官方旧 Workbench 枪械参考网格**。优先 AK-47、M4A4、AWP 已包含在内。此处的“官方”指来源于 Valve 发布的旧 CS:GO 涂装工作包；未建立它们与任一运行中游戏版本 MDL 的逐顶点一致性，也不是 CS2 新版几何。

这批文件提供真实旧版枪械表面形状和 UV 依据，但没有成套材质、骨骼、动画、第一人称手臂或游戏配置。因此它们是可用的原始几何参考，不是已经完整还原的游戏武器。

本轮仅写私有参考区、新转换脚本和本文档；没有修改 `public`、`game`，没有安装插件或操作 SteamCMD。包内也没有单独的通用再分发许可文件；本报告不作公开分发授权判断。

## 确定性转换与保真策略

运行环境为本机 **Blender 5.2.1 LTS**，使用其内置 `mathutils.geometry.tessellate_polygon`。没有使用第三方插件。入口：

```sh
# 默认优先三把
python3 -B scripts/convert-workbench.py

# 全部 34 把；也可 --models ak-47 m4a4 awp
python3 -B scripts/convert-workbench.py --all

# 只审计或只回读已有输出
python3 -B scripts/convert-workbench.py --inventory-only
python3 -B scripts/convert-workbench.py --all --validate-only

# 用实际 Three.js GLTFLoader 独立解析
npx tsx .reference-assets/workbench/validate-three.ts
```

最初的 Blender OBJ 导入/GLB 导出路径被数值门槛拦住：导入轴适配产生了节点旋转，且 AK-47 一个源角点法线从 `(-0.0001,-0.9999,-0.0159)` 改为约 `(-0.0001000,-0.9999048,-0.0138001)`，方向误差约 0.0021 rad。正式产物没有采用该有损路径。

最终转换器直接读取原 OBJ 角点，将原 XYZ、原 UV、归一化后的原法线写为 float32 GLB；Blender **只决定非退化四边形的三角化**。不重建法线、不平滑、不简化、不焊接、不居中、不做单位缩放，也不伪造材质。原组名保留，所有 GLB 节点变换为恒等。每把连续生成两次并检查完整 GLB 字节相同；固定 Blender 版本、输入 ZIP 与脚本时可复现。

OBJ 与 glTF 的二维贴图原点约定不同，所以标准 `TEXCOORD_0` 写入 `(u, 1-v)`，回读按同一明确映射对比。26 把存在超出 `[0,1]` 的源 UV，转换没有裁剪或重新包装。

另有 **16 把、6,719 个源 UV 坐标**的第三分量非零。标准 glTF UV 是二维，为避免静默丢失，转换器把每个源 `vt.w` 保存在自定义顶点属性 `_SOURCE_TEXCOORD_W`；Three.js 已实际读到 `_source_texcoord_w`。标准材质仍只采样二维 UV，额外字段用于保留和研究原数据。

原包还含 **21 个退化四边形**：CZ75 12、Desert Eagle 1、M4A1-S 2、MP9 2、P90 2、USP-S 2。实际检查其中 19 个有重复坐标/零长边，P90 两个的四点共线、面积为零。转换器仅对确证退化的源面使用固定 fan，以保留原角点和面计数；不是新增有效表面。AK-47、M4A4、AWP 都没有此 fallback。

## 实际回读结果

逐输出顶点对照源 OBJ 的位置、UV、原法线方向和第三纹理分量；验证所有使用过的源角点都有对应输出、每个输出三角形属于一个原多边形，且每个原面的三角形数量为 `n-2`。同时校验节点恒等、bounds 和原文件 SHA。原法线按 glTF 约定归一化，保留方向，不承诺原来舍入后略偏离 1 的法线长度。

| 检查 | 34 把最大误差 | 阈值 |
| --- | ---: | ---: |
| 源角点位置 | 1.9331964603e-6 原单位 | 1e-5 原单位 |
| 二维 UV | 1.8127441379e-6 | 2e-6 |
| 原法线方向 | 4.9421560621e-8 rad | 1e-6 rad |
| 源第三纹理分量 | 2.2583007819e-7 | 2e-6 |

AK-47、M4A4、AWP 的法线方向误差分别不超过 4.713e-8、4.215e-8、4.713e-8 rad；三把位置误差分别不超过 9.496e-7、1.934e-6、1.912e-6 原单位。误差来自 float32 存储量化。

第二条独立路径使用项目实际 **Three.js r185 的 GLTFLoader** 解析全部 34 把，检查原始三角形数量、世界 bounds、有限坐标、单位法线、额外 UVW 字段和没有骨骼/动画。34/34 通过，最大 bounds 差为 **1.1962890625e-6 原单位**。这些是结构和数值证据，本轮没有进行材质/GPU画面验收。

## 对后续工作的价值与缺口

最有价值的现成基础是 34 把官方旧式枪械的表面轮廓、细节网格、逐角点法线和配套 UV 模板，可替代凭空重建的枪形，并为后续真实材质匹配提供坐标依据。优先三把已直接具备可加载的私有 GLB。

下一步仍需由完整原游戏资源建立版本、单位/轴向、原表面纹理与 shader 参数、viewmodel/世界模型差异、原骨骼与动画、socket 和手部配合的对应关系。不同 OBJ 的原点与包围盒位置差异很大，不能统一居中后假定枪口、握把或肩托会对齐。当前灰色默认显示只代表静态几何能加载，不能作为原枪完整还原交付。
